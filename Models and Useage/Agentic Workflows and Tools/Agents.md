## 🧠 Agent Overview
These agents run in *read‑only* (static‑analysis) mode on source code but **create / update documentation artifacts**.

| Agent | Role |
|-------|------|
| **AnalyzerAgent** | Parse project structure, build dependency graphs |
| **IntentAgent**   | Deduce high‑level *architectural style* and constraints |
| **DocGenAgent**   | Produce human‑readable docs from analysis outputs |
| **GraphAgent**    | Render visual diagrams (Mermaid / Graphviz / etc.) |

---

## ⚙️ Agent Lifecycle
1. **Initialization** – Agent is invoked for supported file types or tasks.  
2. **Discovery** – Walk directory tree; collect modules, file types, build configs.  
3. **Analysis** – Static / semantic inspection; store intermediate model.  
4. **Documentation** – Emit Markdown/diagrams into `{{docs_dir}}`.  
5. **Finalization** – Stage output for review (PR, commit, or preview site).

---

## 🧠 Key Detection Goals
- **Architecture:** Analyzer + IntentAgents should categorize the system’s *overall architecture* (layered, microservices, MVC, hexagonal, etc.) based on code cues—no exhaustive list required.  
- **Design Patterns:** Note any common design patterns (singleton, observer, factory, etc.) when they materially affect comprehension. List only patterns that actually appear.

## 🛠️ Implementation Considerations

### Analysis Approach

* Prefer **static analysis** (AST, reflection, compiler APIs) over execution.
* Use language‑appropriate tooling (Python `ast`, JS Babel/TS‑API, JavaParser, Roslyn, etc.).

### Error Handling

* On partial failures, still emit docs with clear *warnings*; do not abort entire run.

### Performance

* Reuse prior agent outputs to avoid recomputation.
* Agents may run **in parallel** on independent tasks when the orchestration layer allows.

* `## Overview` – Purpose & scope

* `## Components` – Key modules/classes
